# AC-T02 Phase 2 integration runner

This package prepares a host-side runner that attaches a short-lived .NET SDK container to the existing Phase 1 internal database network. It does not start, stop, recreate, or remove the PostgreSQL container. The runner is intentionally not executed as part of this package implementation.

## Preconditions for a later authorized run

- An operator has explicit approval for the exact Phase 2 test run and cleanup scope.
- Phase 1 PostgreSQL is running and healthy under project `pitcrm-ac-t02-da13f183`, service `postgres-test`, with its original protected run-id, image digest, 768 MiB memory, 0.50 CPU, 128 PIDs, 64 MiB shared memory, and 256 MiB protected tmpfs. Its `pitcrm-test` network must be internal and contain only that database before the runner starts.
- The operator runs as the owner of `/home/carlos`; Phase 1 state remains mode `0700`, its run-id and password remain owner-only mode `0600`, and the password is 64 lowercase hexadecimal characters. Phase 1 credential files and PostgreSQL state are never changed by this package.
- The source worktree and backend subtree are clean of nested mounts, canonical (without symlink path components), and readable/traversable by the operator. The worktree is at the supplied commit and descends from `da13f183ac8bbaaec6c4635ce888e7590fa0cdb4`. Source/cache ownership and group-write permissions may differ because they are copied to private per-run snapshots. Symlinks, special files, unreadable paths, submounts, insufficient free space, or any detected source change during copy fail closed. The current package branch must be committed and reviewed before the clean-tree preflight can pass.
- `/home/carlos/openbot/workspace/.tools/nuget-packages` exists on the VPS host, has no nested mounts, is canonical and readable/traversable by the operator, and contains every dependency needed by the solution and the probe. The runner uses a content-verified cache snapshot under the owner-only run state; both snapshots are mounted read-only. NuGet sources are cleared inside the runner; restore is offline and fails closed if the cache is incomplete.
- The pinned .NET SDK base image is already available locally for `linux/arm64`. Its manifest digest is `sha256:dbcd91573287583286212aaa14ae39ccf04f80818b33e2770dbbd5d948d23230`, from Microsoft's Artifact Registry entry for [`dotnet/sdk:10.0.302-azurelinux3.0`](https://mcr.microsoft.com/en-us/artifact/mar/dotnet/sdk/tag/10.0.302-azurelinux3.0). The host runner builds with `--network=none` and `--pull=false`.
- Host `MemAvailable` is at least 2,883,584 KiB (2.75 GiB) before the run, reserving the runner's 1,536 MiB cap, PostgreSQL's 768 MiB cap, and 512 MiB for the host. The runner is capped at 1 CPU and 128 PIDs; PostgreSQL keeps its independent Phase 1 caps.
- Host `flock`, `jq`, and GNU `timeout` are available. An owner-only lock serializes runner starts so two operator invocations cannot attach competing test containers to the Phase 1 network.

## Run and recover

After approval, use a clean, exact source commit and pass its full SHA:

```bash
ops/ac-t02/phase2/run-integration-tests.sh /path/to/pit-crm <full-commit-sha>
```

The host preflight validates the exact Phase 1 container by Compose project/service/run-id; health, image/digest, architecture, resource and tmpfs settings; network isolation and absence of published ports/persistent volumes; source path/commit/cleanliness; credential ownership/modes; and dynamic available memory.

The worktree accessibility scan prunes generated `bin`/`obj` directories only for backend source. Before archive creation, the runner rejects any committed backend path containing a `bin` or `obj` component, so generated outputs cannot enter the source snapshot. The NuGet cache scan remains complete. Run `bash ops/ac-t02/phase2/test-snapshot-preflight.sh` for local checks of these rules without Docker or a database.

Before container creation, the host creates run-id-specific owner-only snapshots without changing shared permissions or ownership. Backend source comes from `git archive` at the exact approved commit, then is checked for symlinks, unsafe modes, and readability. The NuGet cache snapshot helper hashes and inventories the shared cache before copying, copies regular files without following symlinks, then rechecks both source and snapshot; any path, metadata, or content change during the copy fails closed. A disk preflight estimates source and cache sizes and requires 128 MiB of spare space; the cache helper independently requires 64 MiB remaining after source extraction. Both snapshots are bind-mounted read-only. Shared source/cache directories are never modified. The runner copies backend source into its disposable container layer and strips copied `bin`/`obj` build artifacts; `.dockerignore` excludes build outputs from the image context. Before start, the host verifies the effective created container configuration: exact single network, exact three read-only binds, no ports/volumes, exact memory/CPU/PID caps, no privileged mode or added capabilities, all capabilities dropped, and `no-new-privileges`. The runner runs unprivileged, has no Docker socket, host networking, published ports, or persistent volume, and joins only the internal DB network. Each invocation uses a random run-id image tag; its run-id label and image ID are recorded in private state. Cleanup removes only that tagged image after its runner container is gone and only if no container references it, then removes that run's private snapshots.

Before `dotnet test`, a standalone Npgsql probe opens TCP from the runner and checks the database/user, port, and server IP against the exact container IP found during preflight. Only then does the runner restore offline and invoke these complementary integration tests: `CustomersApiTests` (commercial numbers, concurrent allocation, organization isolation, assignment gate, typed references and origin/send-channel separation) and `CommercialTrackingMigrationTests` (synthetic legacy fixture, stable IDs/creator foreign keys, deterministic ordering, organization/year numbering, and legacy origin normalization). The API test startup applies migrations only to its unique schema inside the disposable database; the migration fixture uses another unique schema. Successful runs emit only the test summary. Failed runs emit normal test logger details through the probe's sanitizer: it replaces the known database password and long hex tokens, and suppresses lines matching common connection-string fields, credential assignments, bearer tokens, or URL user-info. The failure name, exception, and stack remain visible when they do not share a line with detected credentials. Run `dotnet build --configuration Release ops/ac-t02/phase2/connection-probe/ConnectionProbe.csproj` then `bash ops/ac-t02/phase2/test-sanitize-test-log.sh ops/ac-t02/phase2/connection-probe/bin/Release/net10.0/ConnectionProbe.dll` for local checks. This is defense in depth, not a universal secret detector: unknown credential formats or secrets embedded in arbitrary text may need additional redaction rules; raw logs are never printed if sanitization fails.

Normal exit, failure, timeout, and handled SSH disconnects call `cleanup-runner.sh` with the generated runner run-id. Cleanup validates the saved run-id metadata and image ownership label and refuses image removal while any container still references the image. If the host shell is forcibly killed, use the run-id printed at start after reconnecting:

```bash
ops/ac-t02/phase2/cleanup-runner.sh <runner-run-id>
```

Cleanup verifies the runner's project/service/run-id labels and removes only that runner container and its owner-only state files. It never targets the Phase 1 PostgreSQL container or its state. A later run must be separately authorized; this package does not provision or run tests by itself.
