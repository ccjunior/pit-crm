# Estado do projeto

Atualizado em 20/11/2026.

## Situação

O nome do produto foi aprovado em 14/11/2026: **PIT Obras**. O posicionamento comercial é para empresas de construção civil e reformas. PIT-CRM continua sendo o nome interno do projeto e do repositório. O README, os documentos de produto e os rótulos visíveis do Angular já usam a marca aprovada.

A restilização orientada pela imagem enviada em 14/11/2026 abrange shell desktop/mobile, acesso, visão geral, clientes/locais e formulários de cadastro e demanda. A paleta Project IT foi conferida no site oficial. `npm run build` passou; o Angular mantém um aviso de orçamento no CSS da tela de clientes (7,86 kB; aviso em 6 kB, erro em 8 kB). A conferência visual local cobriu o acesso em desktop e 390 px. Na demonstração T23, telas autenticadas de clientes, locais e demandas foram percorridas como Administrador; gestão de equipe e troca obrigatória de senha ainda não foram inspecionadas manualmente.

A API passou a registrar `UserSecretsId` e README documenta `ConnectionStrings:DefaultConnection` no .NET User Secrets. A connection string local foi salva fora do repositório; `dotnet run` iniciou sem variável de ambiente e `GET /api/health` respondeu `ok`. O processo temporário foi encerrado depois da verificação.

Documentação de descoberta, escopo, modelo operacional e arquitetura disponível. O usuário aprovou a primeira entrega operacional em 05/11/2026. O registro anterior de 17/11 cobria T01–T18; T21 e T24 também estavam implementadas, e T19 era então a próxima tarefa. Schema, provisionamento idempotente, sessão com antifalsificação, políticas iniciais, interface de entrada, clientes/locais, criação, busca e detalhe de demanda e APIs de equipe/senha já haviam sido verificados. O PostgreSQL 18.4 do Compose foi confirmado ativo em `127.0.0.1:5433`; em 20/11, `AddOrganizationDemandNumbers`, `SeedBaseIdentityRoles` e `AddDemandVersion` foram aplicadas a `pitcrm_dev`. Consulta confirmou os três perfis-base e versão 1 na demanda existente. Uma tentativa anterior de provisionar o primeiro Administrador foi revertida; depois o usuário confirmou que um cadastro autenticado de membro da equipe funcionou.

Em 20/11/2026, T19 foi implementada localmente: gestão Angular de equipe, exibição da senha temporária para entrega externa, tela/guardas de troca obrigatória e restrição da rota de equipe ao Administrador. Os 12 testes focados e o build Angular de produção passaram. O Docker Desktop/Compose foi confirmado ativo e saudável nesta sessão. O usuário confirmou cadastro autenticado via API após o seed. A inspeção manual da equipe e da troca obrigatória de senha continua pendente; T23 inspecionou a interface de clientes, locais e demandas.

Correção da T19 em 20/11/2026: os papéis são agora seed de banco na migração `20261120141438_SeedBaseIdentityRoles`, não criação sob demanda no endpoint. A migração preserva qualquer papel já existente pelo `NormalizedName` e inclui os perfis-base ausentes; o endpoint informa quando faltam migrações. A suíte completa do backend passou (7 testes), incluindo migração sobre banco que já continha um Administrador com ID legado. A API local permaneceu ativa em Debug; a migração foi aplicada com build Release separado, sem interrompê-la, e consulta confirmou os três perfis em `pitcrm_dev`. O usuário confirmou que o cadastro autenticado funcionou após a migração.

T20 implementada em 20/11/2026: `PUT /api/demands/{id}` exige a versão atual, valida vínculos da organização e grava a mudança junto à atividade `DemandUpdated`. Uma versão anterior e uma disputa entre gravações retornam 409 sem sobrescrever o vencedor. A migração `AddDemandVersion` cria o token numérico iniciado em 1 e foi aplicada a `pitcrm_dev`; a demanda existente recebeu versão 1. Os 7 testes backend passaram em saída temporária. Durante T23, a API local foi iniciada com o código atual e o PUT foi exercitado pela interface autenticada.

T22 implementada em 20/11/2026: o painel de detalhes abre o formulário de edição com os dados atuais, cliente/local e responsável elegível; o formulário envia a versão ao PUT, mantém os valores após erro, oferece recarga explícita após 409 e atualiza lista/detalhe após sucesso. Os testes focados de formulário e integração do painel passaram (11 testes) e o build Angular passou. O build deixou um aviso de orçamento: bundle inicial de 500,10 kB, 99 bytes acima do limite de 500 kB.

T23 executada em 20/11/2026: suíte backend completa 7/7, suíte Angular completa 29/29 e build Angular aprovados. O PostgreSQL Compose já estava saudável; as migrações estavam atualizadas. Uma API local com o código atual respondeu em `/api/health`; no navegador autenticado foram criados cliente, local e demanda sem responsável em Alpha, a edição via PUT registrou atividade e sobreviveu a logout/login, e a conta administradora de Beta viu listas vazias. Os testes de integração cobrem Administrador, Gestor e Operador em duas organizações, além de tentativa de acesso cruzado. A edição foi conferida em 390×844 e 1.280×900 px; travessia de teclado no formulário confirmou foco no cliente, local, descrição e opções de origem, sem overflow horizontal. Os registros sintéticos das duas organizações permanecem em `pitcrm_dev` para inspeção. Limites: inspeção visual manual foi com Administrador; os fluxos dos demais perfis foram verificados pela suíte HTTP automatizada. Resposta de rede perdida não foi injetada manualmente; a cobertura de erros permanece nos testes unitários/integração documentados. O build Angular segue 99 bytes acima do orçamento inicial. Ver [verification.md](features/primeira-entrega-operacional/verification.md). T23 é a próxima tarefa concluída; não há outra tarefa de primeira entrega no roadmap.
